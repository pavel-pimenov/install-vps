# AGENTS.md

Памятка для LLM/агентов, работающих в этом репозитории.

## Проект

Асинхронная утилита `install-vps`: стартовая настройка новой Ubuntu-VPS
(24.04 / 26.04) по SSH-ключу. Работает без внешних Python-зависимостей:
вся связь — локальным системным `ssh`, удалённые действия — одиночным
стримовым bash-скриптом, передаваемым через stdin.

## Рабочие команды (обязательно перед сдачей)

```bash
python3 -m ruff check install_vps    # линтер
python3 -m compileall -q install_vps # компиляция
python3 -m install_vps <host>        # реальный прогон (или --verify-only)
```

Все должно проходить чисто (ruff: 0 ошибок). Кодировка исходников — UTF-8,
длина строки в python-коде — 88 (ruff default), в bash-шаблонах — свободно.

## Как устроен код

- `install_vps/cli.py` — разбор CLI, слияние `config.toml` + флаги,
  точка входа `main()`.
- `install_vps/config.py` — `Config` (dataclass) и загрузка TOML
  (стандартный `tomllib`, без парс-зависимостей).
- `install_vps/ssh.py` — `RemoteHost`: собирает системную команду
  `ssh -p PORT -i KEY [-o ...] USER@HOST`, потоково запускает удалённый
  скрипт через `bash -s` (stdin), стримит вывод в консоль.
- `install_vps/installer.py` — bash-шаблоны (строки с `.format()`),
  `install()` и `verify()`.

## Правила доработок

1. **Аккуратно с sudo/root**: скрипт сам определяет на хосте, root ли
   пользователь; при не-root требует `sudo -n` (NOPASSWD) и падает с
   понятной ошибкой. Не вводить интерактивный ввод пароля sudo.
2. **Пакеты идемпотентно**: скрипт должен безопасно повторяться
   (как `apt-get install -y ...`) и не полагаться на прошлое состояние
   файлов на хосте.
3. **Ubuntu 26.04 = codename «resolute»**: VERSION_CODENAME снимается
   с хоста через `/etc/os-release`, в шаблонах используется плейсхолдер
   `{codename}`. Не захардкоживать «resolute» в установку.
4. **Ненадёжные репозитории**: любой неудачно записанный
   `sources.list.d/*.list` ломает весь `apt-get update`. Поэтому в начале
   скрипта явно `rm -f` испорченный docker-листинг; ключ пишется
   деарморированным (`gpg --dearmor`) в `/etc/apt/keyrings/docker.gpg`
   (сырой арм-ключ apt игнорирует как «unsupported filetype»). Ключ
   и листинг пересоздаются каждым запуском — не полагаться на прошлое
   состояние файлов.
5. **Расширение «новыми установками»** — заводить отдельный bash-шаблон
   в `installer.py` и вызывать в `install()` до/после `PKG_INSTALL`,
   не превращая в один гигантский нечитаемый скрипт.
6. **Файлы конфигурации** — в репозитории лежат примеры `config.toml`
   и `HISTORY.md`. Не создавать лишних файлов без нужды.
7. **История изменений** — ведётся в `HISTORY.md` (Changelog, reverse
   chronological). Правки в коммиты не пушатся без явной просьбы
   пользователя.
