# HISTORY.md

Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/),
версионирование — [SemVer](https://semver.org/lang/ru/). Обратный
хронологический порядок.

## [0.11.0] — 2026-09-29

### Добавлено

- **Опции сайта-статики** в `caddy_site` — хвост после `|`:
  `browse` (листинг каталогов), `index=файл,файл` (приоритет индексных
  файлов), `hide=шаблон,…` (что не показывать в листинге) и
  `deny=шаблон,…` (файлы, которые не отдаются вовсе). Раньше генератор умел
  только `root` + `file_server`, поэтому сайты, мигрированные с lighttpd,
  приходилось держать ручными файлами в `/opt/caddy/sites` — стоило внести
  такой домен в `caddy_sites`, и листинг с 403-молча пропадал бы. Значение
  опции — шаблон имени файла, а не путь: `../etc` и пробелы отклоняются, как
  и любые опции у сайта-прокси, где они бессмысленны. Хвостовой `|` после
  опций допускается, пустая опция между разделителями — нет. У Caddy нет
  директивы `deny`, поэтому это matcher по пути и `respond 403`; в порядке
  директив `respond` и так идёт раньше `file_server`.

## [0.10.0] — 2026-09-28

### Добавлено

- **Централизованный мониторинг**: `beszel_mode` (`hub` по умолчанию, `agent`
  для узла) и флаг `--beszel-mode`. В режиме `agent` поднимается только
  `beszel-agent` на порту 45876 — хаб живёт на другом сервере и сам стучится к
  агенту. Плитка `Мониторинг` в портале узла больше не появляется.
- `beszel_agent_port` / `--beszel-agent-port` и `beszel_agent_allow` /
  `--beszel-agent-allow`: открыть порт агента только перечисленным хостам.
  Правила добавляются лишь при активном ufw; если ufw выключен, скрипт
  предупреждает, что правило не сработало. Установщик сам firewall не
  настраивает.
- `beszel_hub_url` / `--beszel-hub-url`: агент сам подключается к хабу
  исходящим WebSocket. Нужно узлам, чьи провайдеры режут входящие высокие
  порты: тогда `beszel_agent_allow` не требуется и firewall не открывается.
  Без схемы адрес считается `https://`.
- `beszel_version` / `--beszel-version`: образы `henrygd/beszel` и
  `henrygd/beszel-agent` запинены (по умолчанию 0.20.0) — hub и agent должны
  быть одной версии, а `latest` ломает пару при обновлении образа.
- **Portainer CE**: `portainer` / `--portainer` с режимами `server` (по
  умолчанию) и `agent`, отдельный домен `portainer_domain` /
  `--portainer-domain`, порт UI 9443 (только `127.0.0.1`, наружу его отдаёт
  Caddy). UI не проксируется под базовым путём портала — его роутер рассчитан
  на корень, поэтому в портал добавляется внешняя плитка `Контейнеры`.
- Edge-агент регистрируется парой `portainer_agent_edge_id` /
  `portainer_agent_edge_key` (или флагами `--portainer-agent-edge-id` /
  `--portainer-agent-edge-key`) из UI Portainer (Environments → Add environment
  → Edge Agent Standard): у Portainer 2.45.1 нет join-токена. Агент сам ходит
  на сервер, входящих портов не открывает. Создавая окружение, указывайте его
  публичный URL (`https://portainer.example.com`) — иначе в ключе окажется
  внутренний адрес.
- Туннель edge-агентов слушает 80 **внутри** контейнера сервера
  (`--tunnel-port=80`) и опубликован только на `127.0.0.1:8000`; наружу его
  отдаёт отдельный сайт Caddy `portainer-tunnel`, который пропускает в
  `reverse_proxy` только WebSocket-upgrade, а обычные запросы уводит на HTTPS.
  Клиент chisel собирает `ws://` только для http/wss-строк, поэтому без
  маршрута через Caddy по 80-му порту туннель недостижим.
- `portainer_version` / `--portainer-version`: образы Portainer CE и агента
  запинены (по умолчанию 2.45.1) — сервер и агенты должны совпадать.
- Перевод сервера с «хаб+агент» на «только агент»: compose перезаписывается,
  бывший контейнер хаба удаляется через `--remove-orphans`.
- `--portainer-admin-password`: окно создания первого администратора в UI
  Portainer длится 5 секунд, иначе портал больше его не предложит. Пароль
  кладётся на хост отдельным файлом 0600 (`/opt/portainer/admin-password`) и
  контейнеру передаётся через `--admin-password-file`, поэтому он не светится
  ни в compose, ни в `docker inspect`. Без флага проверка честно предупреждает
  про окно.
- Постоянные access-логи Caddy: `caddy_access_log` (по умолчанию `true`),
  JSON в stdout с ротацией Docker и без буферизации ответа
  (`flush_interval -1`) — иначе по медленному каналу страница мониторинга
  выглядит «белой»: браузер получает начало HTML, но не дожидается JS.
- **Сайты-статика**: `caddy_site` вида `домен=file:/каталог` (и `static:`) —
  Caddy отдаёт каталог как сайт с `file_server` и `encode`. Каталоги `/etc/caddy`,
  `/srv/portal`, `/data`, `/config` запрещены (mount перекрыл бы конфиг,
  сертификаты или страницу портала).
- Превентивная проверка чужого контейнера `caddy`: если имя занято контейнером
  из другого compose-проекта, установщик останавливается и печатает, что
  сделать, но чужой контейнер не переименовывает и не удаляет.

### Исправлено

- **Две ошибки, которых не видит `bash -n`**: лишние кавычки в присваивании
  `PORT_TUNNEL_CODE` (падало под `set -u`) и перенос строки внутри `$(...)` —
  `curl` получал обрезанную команду без URL. Оба случая закрыты assert'ами в
  тестах.
- Edge-ключ Portainer разбирается до похода в SSH (base64
  `url|host:port|fingerprint|endpoint_id`): сверяется с `portainer_domain`,
  проверяется UUID агента и что ID и ключ заданы вместе — иначе агент принимает
  ключ молча и просто не регистрируется.
- `PORTAINER_STACK` снимает контейнер с нужным именем (`docker rm -f`) перед
  `up -d`: при смене compose-проекта Docker падал на конфликте имён.
- Проверка порта агента Beszel больше не ругается в режиме `beszel_hub_url`,
  где соединение инициирует агент, а не хаб.
- **Статика отдавала 404 на каждый файл.** Caddy работает с
  `network_mode: host` и не видит файловую систему хоста, а каталоги статики в
  compose не монтировались. Теперь каждый каталог из `caddy_site` добавляется
  отдельным read-only mount, а отсутствующий каталог даёт явное предупреждение
  вместо молчаливого пустого каталога от Docker.
- **Повторный прогон после неудачной установки падал на Caddy.** Хеш пароля
  портала считается через `docker exec` в живом контейнере, поэтому контейнер
  теперь поднимается до генерации сайтов, а `portal.caddy` с заглушкой
  `__PORTAL_HASH__` (или с пустым хешем) от прошлого прогона удаляется перед
  стартом вместе с пересозданием контейнера: после серии падений docker держит
  паузу перед рестартом, и без пересоздания он продолжил бы читать старый
  конфиг. Шаблон проверки хеша — ERE, а не BRE (`\|` в ERE это литеральный
  пайп, из-за чего валидный `$2a$…` никогда не совпадал и заглушка считалась
  битым файлом на каждом прогоне).
- `BESZEL_VERIFY` больше не содержит заглушек: проверка хаба и проверка порта
  агента выбираются по режиму, Go-шаблоны `docker ps` экранированы для
  `str.format` (в статусе агента печаталось литеральное `{.Status}`).
- Предупреждение «не задан `beszel_agent_key`/`beszel_agent_token» смотрит в
  записанный compose, а не в конфиг: при ключе, сохранённом с хоста, агент
  ругался на пустой конфиг при полностью рабочей связке с хабом.
- `--verify-only` для Portainer проверяет то же, что и установка: ответ UI на
  `127.0.0.1:<port>/api/status`, слушающий порт туннеля edge-агентов и файл
  начального пароля с правами 0600. Раньше он проверял только контейнер.

## [0.9.0] — 2026-09-27

### Добавлено

- **Единый вход на портал** (`portal_user`, `portal_password`, флаги
  `--portal-user`/`--portal-password`): Caddy включает `basic_auth` на домене
  портала, браузер спрашивает логин и пароль один раз, и дальше все плитки
  открываются без форм. Пароль считает сам Caddy (`caddy hash-password` через
  stdin, чтобы не светился в `ps`), на диск попадает только bcrypt-хеш.
- Собственный вход Dozzle при заданном `portal_password` не создаётся:
  логи закрывает пароль портала, лишнего запроса пароля больше нет.
  Проверка запрещает выносить такой Dozzle на отдельный домен через
  `caddy_sites`, где пароль портала не действует.
- `--verify-only` проверяет, что анонимный запрос к порталу получает 401, а
  запрос с паролем — 200, и ходит в плитки с credentials.
- `config.local.toml` в `.gitignore` — место для локальных секретов (пароль
  портала, ключи агента), чтобы они не попадали в репозиторий.

### Исправлено

- Проверка «закрыт ли портал паролем» слала пароль и поэтому всегда получала
  200 — анонимный запрос теперь уходит без credentials.

## [0.8.1] — 2026-09-27

Все четыре бага найдены прогоном с нуля на чистом Ubuntu 26.04
(`vpn.fly-server.ru`, 1 vCPU, 453 МБ RAM) — на боевом хосте они не
воспроизводились, потому что нужное состояние файлов уже существовало.

### Исправлено

- **Установка падала на пустом хосте.** Чтение прежнего `KEY`/`TOKEN` агента
  из `/opt/beszel/docker-compose.yml` шло `sed` по файлу, которого на
  свежем хосте ещё нет: код 2, а вместе с `pipefail` и `set -e` это
  останавливало весь скрипт. Теперь чтение под `[ -f ... ]`.
- **Смена пароля Dozzle не действовала.** Контейнер держит `users.yml` в
  памяти, поэтому после перезаписи файла вход оставался 401, пока
  контейнер не пересоздать. Теперь при перезаписи `users.yml` контейнер
  пересоздаётся (`--force-recreate`), а в остальных прогонах не трогается.
- **Ложное `MISSING` портала на первом прогоне.** Проверка шла сразу после
  `caddy reload`, пока Caddy ещё выпускал сертификат: TLS не проходил и код
  ответа был 000. Теперь проверка ждёт непустой код (до 90 с).
- Перезапускающийся контейнер больше не рапортуется как `OK`: агент Beszel
  без ключа падает в цикл, и теперь печатается `ПРОБЛЕМА` с подсказкой
  задать `beszel_agent_key`/`beszel_agent_token`.

### Документация

- **Beszel на самом деле работает под путём портала** — ограничение касалось
  только ThinPro. `install-vps` прописывает Hub `APP_URL` вместе с путём
  (`https://<домен>/monitor`), и Beszel генерирует все ссылки с префиксом:
  ассеты и API отдаются с 200 под `/monitor/` (проверено на чистом узле).
  Прежнее утверждение в README и конфиге было неверным.

## [0.8.0] — 2026-09-26

### Добавлено

- **Логи контейнеров в браузере: Dozzle.** `dozzle` (`--dozzle`) — контейнер
  `amir20/dozzle:v11.1.1` в `/opt/dozzle`, слушает только `127.0.0.1:8082`
  (`dozzle_port`), наружу его отдаёт Caddy. Отдельный домен не нужен: Dozzle
  живёт под базовым путём портала (`dozzle_path`, по умолчанию `/logs`,
  `DOZZLE_BASE`), плитка `Логи` появляется сама. Прокси сохраняет префикс
  (`handle`, а не `handle_path`) и не буферизует поток (`flush_interval -1`,
  `read_timeout 3600s`) — без этого SSE-логи приходят пачками или не приходят
  вовсе.
- Вход по паролю: `dozzle_user` / `dozzle_password`. Если пароль не задан, он
  генерируется на хосте и печатается один раз; `users.yml` (bcrypt) больше не
  перезаписывается, поэтому повторный прогон не сбрасывает уже известный
  пароль. Свой пароль — единственный способ сменить существующий. Внутри
  выключены shell и actions (доступ к `docker.sock` из веба равен root на
  хосте), аватары и аналитика.
- `DOZZLE_VERIFY` — проверка контейнера и ответа на `127.0.0.1:<port><path>/`
  в `--verify-only`; 30x на форму входа и 401 считаются успехом (значит
  авторизация включена), код печатается рядом с плиткой портала.

### Исправлено

- Плитка портала под прокси больше не печатает литерал `($CODE)`: сообщение
  было в одинарных кавычках, где `$CODE` не подставляется. Название плитки
  теперь проверяется на кавычки, доллар, обратный слэш и управляющие символы
  — оно попадает в строки проверочного bash.
- Ложное `MISSING` в проверке контейнеров: шаблон `docker ps --format` терял
  пару скобок при подстановке, и имя контейнера не читалось вовсе.

## [0.7.0] — 2026-09-26

### Добавлено

- **Портал с плитками сервисов.** `caddy_portal` (`--caddy-portal ДОМЕН`) —
  страница `https://<домен>/` со списком сервисов этого сервера: тёмная
  сетка плиток, без внешних шрифтов и скриптов, `noindex`. Страница
  генерируется в `/opt/caddy/portal/index.html` и отдаётся контейнером Caddy
  как статика (`./portal:/srv/portal`), каталог монтируется всегда.
- Плитки `caddy_tiles` (`--caddy-tile`, можно повторять), два вида:
  `Название=/путь=upstream` — Caddy проксирует путь на локальный сервис и
  срезает префикс (`handle_path`, приложение видит `/`); `Название=https://домен`
  — внешняя ссылка. Четвёртое поле `=keep` оставляет префикс — для
  приложений, которые сами знают свой базовый путь.
- Плитка мониторинга появляется сама: `beszel_path` (по умолчанию `/monitor`)
  → `127.0.0.1:<beszel_port>`, с настройками Beszel из его документации
  (`read_timeout 360s`, тело до 10 МБ). `APP_URL` Hub берётся оттуда же, так
  что в уведомлениях и конфиге агента — публичный HTTPS-адрес. Если мониторингу
  выделен свой домен (`caddy_domain`), автоплитки нет: плитку на портале надо
  описать External-ссылкой.
- Путь без завершающего слэша (`/monitor`) отдаёт 308 на `/monitor/`, иначе
  прокси его не ловит.
- `CADDY_PORTAL` — проверка портала на хосте: страница отдаётся и каждая
  плитка отвечает (`curl --resolve` по 127.0.0.1, где Caddy слушает из-за
  `network_mode: host`); неотвечающий сервис помечается WARN. Работает и в
  `--verify-only`.
- **Утилиты из релизов GitHub.** `--tools lazydocker bandwhich` (ключ
  `tools`) — установка в `/usr/local/bin` с закреплённой в коде версией и
  обязательной проверкой sha256 архива; версия считается установленной, если
  sha256 уже стоящего бинарника совпал с закреплённым (повторный прогон
  ничего не качает). `EXTRA_TOOLS_VERIFY` работает и в `--verify-only`.
- `swap_size_mb` (`--swap-size-mb`) реально применяется: раньше поле
  было в конфиге, но игнорировалось, размер свопа был зашит в шаблоне.
  `0` — не создавать своп-файл.
- Тесты: `tests/` на `unittest` без зависимостей — слияние конфига, отсев
  некорректных доменов/путей плиток/адресов, генерация Caddyfile и
  compose, и `bash -n` по собранному скрипту (ловит незакрытые `if`/
  кавычки/heredoc в шаблонах). `scripts/check.sh` теперь гоняет их вместе
  с ruff и compileall.
- Версия пакета берётся из `install_vps.__version__` (`dynamic = ["version"]`):
  в `pyproject.toml` стояло 0.1.0 при `__version__ = 0.6.0`.

### Исправлено

- Повторный прогон без `beszel_agent_key`/`beszel_agent_token` больше не
  затирает ими рабочий compose: прежние значения читаются из
  `/opt/beszel/docker-compose.yml` и подставляются обратно. Раньше такой
  прогон тихо ломал уже настроенный агент (пустые `KEY`/`TOKEN`).
- В корневой Caddyfile попадала лишняя пустая строка в конце — Caddy при
  каждом старте писал «Caddyfile input is not formatted». Сгенерированные
  файлы теперь проходят `caddy fmt` без правок.
- `redir /monitor/ 308` в Caddyfile тихо ничего не делал: у `redir` первый
  позиционный аргумент — матчер, поэтому редиректом становился сам путь, а
  запрос без слэша уходил в catch-all. Правильно — `redir * /monitor/ 308`;
  на это есть тест.
- Каталог утилит из WIP-коммита `c05001c` был выдуман: у `bandwhich`
  репозиторий переехал в `imsnif/bandwhich` (версия 0.23.1, а не 0.23.2), а
  `.deb`-ассеты `systemd-manager-tui` отдают 404 — утилита убрана из
  каталога, чтобы не предлагать то, что не ставится. Хеши пересчитаны по
  фактическим файлам релизов (архив + бинарник), архитектуры — по
  `uname -m` (`x86_64`, `aarch64`, `armv7l`, `armv6l`).
- Конфликт в конфиге (битый домен, вложенные пути плиток, `caddy_tiles` без
  портала) теперь ловится до похода в SSH, а не во время сборки скрипта.
- `vmstat` проверялся дважды подряд в `VERIFY`; убран дубль.

### Известные ограничения

- **ThinPro нельзя проксировать под путём.** Он отдаёт разметку с
  `/assets/...`, `/api/...` от корня, поэтому под префиксом (`/thinpro`)
  вёрстка и запросы API ломаются — проверено на боевом хосте, плитка ведёт на
  собственный домен. С Beszel ограничение снято: `install-vps` прописывает Hub
  `APP_URL` вместе с путём, и он генерирует все ссылки с префиксом (проверено
  на чистом узле 27.09.2026 — прежнее утверждение в README было неверным).
  Проксируемые плитки (`Название=/путь=upstream`) остаются для приложений,
  которые живут под префиксом: статики, тихих API и страниц без абсолютных
  путей.


## [0.6.0] — 2026-09-25

### Добавлено

- Вход в Beszel через OAuth2 (Google/GitHub/любой поддерживаемый провайдер) без
  локального пароля: `--beszel-user-creation` (`USER_CREATION=true`) и
  `--beszel-disable-password-auth` (`DISABLE_PASSWORD_AUTH=true`), одноимённые
  ключи `config.toml`. Провайдер добавляется в веб-UI Hub:
  `/_/#/settings` -> выключить «Hide collection create and edit controls» ->
  коллекция `users` -> Options -> OAuth2, redirect URL
  `<домен>/api/oauth2-redirect`.
- `DISABLE_PASSWORD_AUTH` нельзя включить без `USER_CREATION`: иначе новые
  пользователи не смогут войти через OAuth, и доступ к Hub будет потерян.
  Проверка выполняется на стороне Python до отправки скрипта на хост.
- При отключении пароля печатается напоминание с адресом настроек OAuth.

## [0.5.0] — 2026-09-25

### Добавлено

- `CADDY` — обратный прокси с автоматическим HTTPS: `caddy:2-alpine` в
  `/opt/caddy`, `network_mode: host` (сам занимает 80/443 и ходит в
  `127.0.0.1:<порт>`, поэтому чужие compose-проекты не нужно переделывать).
  Сертификаты Let's Encrypt выпускаются и продлеваются сами; HTTP
  перенаправляется на HTTPS. Флаги `--caddy`, `--caddy-email`, `--caddy-domain`
  (Beszel) и `--caddy-site ДОМЕН=UPSTREAM` (любой другой сайт, можно
  повторять), одноимённые ключи в `config.toml`.
- Сайты лежат отдельными файлами в `/opt/caddy/sites/*.caddy`, корневой
  Caddyfile подключает их через `import` — новый сайт добавляется одним файлом.
  Для Beszel используется конфигурация из его документации: `max_size 10MB`
  (импорт/экспорт) и `read_timeout 360s` (долгие опросы и WebSocket агентов).
- `CADDY_VERIFY` — проверка контейнера, занятости 80/443, валидности Caddyfile
  и списка доменов; работает и в `--verify-only`.
- При `--caddy --caddy-domain` у Beszel выставляется публичный
  `APP_URL=https://<домен>` вместо `http://localhost:8090` — иначе в ссылках
  уведомлений и сгенерированном конфиге агента остаётся локальный адрес.
- Домены и upstream валидируются на стороне Python (строгие регулярки), до
  отправки скрипта на хост: `rm -rf /`, `javascript:...` и мусор в домене
  отклоняются с `ValueError`.

### Исправлено

- Caddy не подхватывал обновлённый Caddyfile при повторном прогоне: конфиг
  примонтирован, но процесс держит старый в памяти. Теперь после записи
  выполняется `caddy reload` (при неудаче — перезапуск контейнера), так что
  повторный запуск действительно применяет изменения.
- `import` в Caddyfile указывал на хостовый путь `/opt/caddy/sites`; внутри
  контейнера сайты лежат в `/etc/caddy/sites`, поэтому ни один сайт не
  подключался и 80/443 не открывались.

## [0.4.0] — 2026-09-25

### Добавлено

- `UNATTENDED_UPGRADES` — `/etc/apt/apt.conf.d/52unattended-upgrades-local`
  с `Dpkg::Options` (`--force-confdef`, `--force-confold`). Без них фоновое
  обновление без tty зависает на вопросах debconf/ucf об изменённых конфигах.
  Если установлен `needrestart`, выставляется `NEEDRESTART_MODE=a`; иначе его
  не трогаем. Повторный прогон идемпотентен.

### Исправлено

- **Критично: `zram` не поднимался после перезагрузки.** На VPS с 704 МБ RAM
  `systemd-zram-generator` падал с `ENOMEM` (`Committed_AS` выше `CommitLimit`)
  и не повторял попытку, поэтому в swap оставался только `/swapfile`.
  Теперь вместо генератора ставится `zram-swap.service` +
  `/usr/local/sbin/zram-swap-up`, который стартует позже, когда память уже
  разгружена: уменьшает размер по шагам (`256→128→64→32` МБ) до первого
  успеха, ограничивает каждую запись в `disksize` таймаутом (иначе ядро может
  уйти в своп-цикл), не даёт запросить zram больше физической RAM и корректно
  переживает отсутствие `/proc/meminfo`. Конфиг генератора сохранён.

## [0.3.0] — 2026-09-25

### Добавлено

- `ZRAM` — сжатый своп через пакет `systemd-zram-generator`:
  `/etc/systemd/zram-generator.conf` (`zram-size`, `compression-algorithm = zstd`).
  Активируется сразу (`/dev/zram0`, приоритет 100 — выше обычного swapfile).
  Включается `--zram-size-mb
  256`; по умолчанию выключено (`0`), чтобы не менять поведение молча.
  *См. 0.4.0: загрузочный путь перенесён на собственный юнит.*
- `JOURNALD_LIMIT` — лимит systemd-журнала через drop-in
  `/etc/systemd/journald.conf.d/10-size-limit.conf` (`SystemMaxUse`,
  `SystemKeepFree=200M`, `MaxRetentionSec=2week`) + `journalctl --vacuum-size`.
  На 4 ГБ VPS журнал иначе съедает диск.
- `DOCKER_LOGROTATE` — `log-driver=json-file` с `max-size`/`max-file` в
  `/etc/docker/daemon.json`. JSON мерджится, а не перезаписывается: чужие ключи
  (например `storage-driver`) сохраняются, невалидный файл не трогается ( docker
  продолжает работать с прежней конфигурацией), рестарт `docker` — только при
  фактическом изменении файла. Флаги: `--docker-log-max-size`, `--docker-log-max-file`.
- Флаги `--zram-size-mb`, `--journald-max-use`, `--docker-log-max-size`,
  `--docker-log-max-file` и одноимённые ключи `config.toml`.
- `apply_overrides` переведён на таблицу `_OVERRIDES`: перекрытия конфига
  флагами не размножаются по числу полей (ruff PLR0912).

### Исправлено

- **Критично: `KEYRING_CLEANUP` больше не сносит ядро, на котором работает.**
  `apt-get purge --auto-remove` однажды удалил `linux-modules-*` и
  `linux-image-*` текущего ядра: на хосте пропал `/lib/modules` целиком, в
  `/boot` не осталось `vmlinuz`, то есть хост не перезагрузился бы. Текущее
  ядро защищено точным списком (`grep -Fxv`), `--auto-remove` убран, а если
  пакет образа текущего ядра отсутствует — он ставится заново, и наличие
  `/boot/vmlinuz-$(uname -r)` проверяется с предупреждением.
- `zram` без модуля ядра больше не валит скрипт: при недоступном
  `/sys/block/zram0` выводится предупреждение «заработает после перезагрузки».
- Литералы `{}` в python-фрагменте `DOCKER_LOGROTATE` экранированы
  (`{{}}`) — иначе `.format()` считал их плейсхолдерами.

- Валидация `beszel_agent_key` / `beszel_agent_token`: кавычка или перевод

  ненадёжных `sources.list.d`).
